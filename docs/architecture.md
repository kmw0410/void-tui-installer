# Architecture and protocol v1

Security hardening (2026-10-19): both configuration boundaries reject ASCII controls, including NUL, LF and DEL, in original string values. Bash does this before command substitution can normalize the value. Disk paths share the canonical whole-device name grammar `/dev/[a-zA-Z0-9_-]+`; identity records are limited to 1024 bytes. Disk safety and identity checks run directly before both sgdisk commands and each mkfs command. These repeated checks narrow the check/use window; they are not an atomic lock against hotplug or hostile root activity.

Event/log sanitization strips ANSI/OSC sequences and Unicode format controls, and redacts the password both before and after normalization so removing controls cannot reconstruct a visible secret. Preparation subprocesses use a separate process group; after the direct child exits or cancellation reaches WaitDelay, the remaining group receives SIGKILL. This also closes inherited installer-lock descriptors in surviving descendants. The OS reaps orphaned child processes; the Go process waits for its direct subprocess and stream-copy completion.

The optional `timezone` configuration field defaults to UTC for compatibility. Go and Bash independently validate the original value against the same embedded `scripts/timezones.json` allowlist before installation. The list contains UTC and the public-domain IANA zone.tab names. The target explicitly installs tzdata, verifies the selected TZif file and `/etc/localtime` link, and adds no NTP service. The UI offers a searchable list between Account and Network, with compact navigation at short terminal heights.

KDE and niri share NetworkManager DHCP/static rendering, service conflict checks and `network` group membership. Console-only installations retain dhcpcd. Niri starts a single polkit-gnome agent and delegates Xwayland bridge lifecycle to its built-in xwayland-satellite integration. Standard user directories are initialized as the target user with an explicit HOME and English UTF-8 locale; niri reruns the packaged updater at session startup.

The UI owns discovery, input, review, and exactly one engine session. Bash owns all installation operations. No disk-changing command is used by discovery or preflight. The TUI startup explicitly prepares missing Live tools before discovery. Embedded scripts are extracted to a private temporary directory.

Configuration: JSON object on stdin, at most 64 KiB. Fields: version (1), disk (canonical /dev path), identity (lsblk disk identity string defined below), username, hostname, network (dhcp/static), interface, address (IPv4/CIDR), gateway (IPv4), dns (IPv4), confirmation (exact `ERASE <disk>`). No password in this object. Secret: one UTF-8 password line on inherited FD 3; 8–128 bytes, printable ASCII, no colon, newline or control characters. Only the selected user receives this password. Root is locked with usermod -L; final shadow checks require a locked root entry and a valid user SHA512 hash. The user belongs to wheel and sudo requires authentication. FD 3 closes after reading. Config and secrets are never logged. Never use eval.

Settings persistence has a separate versioned JSON envelope with an explicit public-field allowlist. F5 saves from Review; F9 loads before installation after Live preparation. Passwords and confirmation are omitted entirely. Files are bounded to 64 KiB, checked as regular files with O_NOFOLLOW/O_NONBLOCK, and written as mode-0600 temporary files with fsync plus atomic rename. Existing unrelated files/symlinks are not replaced. Loading validates the public configuration, clears secrets/consent and previous checks, rediscovers disks/interfaces, invalidates changed identities, and returns to Mirror for revalidation. The default home-directory path is on volatile storage in a typical Live session; persistence requires a user-selected persistent destination.

Review invokes --check-install with public configuration only, using a synthetic confirmation solely to reuse public validation. This mode never reads FD 3 or enters destructive stages. It acquires the installer lock, resolves the full package transaction in private metadata, verifies graphics and disk safety/capacity, and emits allowlisted JSON check records. Diagnostics remain on stderr. Go retains partial results on failure, rejects malformed reports and uses a generation plus a serialized public-configuration key to reject stale results. Install requires a successful report for the current configuration and a fresh exact user-entered erase phrase. Retry clears consent; the real engine repeats preflight before partitioning.

Package focus cycles Search, Show selected only, list, Continue. The selected-only checkbox intersects checked names with the current name/description filter. Removing a selected item immediately hides it and clamps the highlighted index, including an empty list. This filter does not alter selections by itself and is not persisted as installation configuration.

Disk identity: Go and Bash use `lsblk -bdn -o MAJ:MIN,SIZE,LOG-SEC,SERIAL,WWN -- <disk>`, trimming surrounding whitespace only. A fresh canonical path, identity, whole-disk type, writable/non-removable flag, minimum 16 GiB size, descendant mounts/swap/holders, and live-medium ancestry are required. Unknown storage dependencies fail closed. Removable disks are excluded in this release. Immediately before erase the identity and complete safety checks run again. Devices with no lsblk serial AND no WWN are excluded. This restricts some QEMU disks: assign a serial. The Bash boundary also checks raw device users with fuser; diagnostics or unknown outcomes block installation.

Events: stdout is JSON Lines only, max 64 KiB/line. Each event has version:1, type (`stage`, `log`, `result`); optional name/status/level/message. Stage names in order: preflight, partitioning, filesystems, bootstrap, system, network, software, grub, snapper, verification, cleanup. Stage status running/completed/failed. Result status success/failed/cancelled. Diagnostic command output is stderr, sanitized by the Go boundary. Exit zero AND success result AND valid stage progression are required for success. Do not emit raw config, commands containing secrets, or passwords in events/errors. Engine failures report a fixed message and current stage; command diagnostics remain stderr. Password-setting stderr is suppressed.

Go types exported from internal/installer: Config (fields Version int, Disk, Identity, Username, Hostname, Network, Interface, Address, Gateway, DNS, Confirmation string, JSON snake_case); Disk (Path, Model, Size, Type, Identity, Reason string; Safe bool). Discover() ([]Disk,error), DiscoverContext(ctx), Interfaces() ([]string,error), Preflight() error, PreflightContext(ctx). Config.Validate() error. Event (Version int, Type, Name, Status, Level, Message string). Start(ctx context.Context, config Config, password string) (*Session,error); Session.Events <-chan Event, Done <-chan error, LogPath string, Cancel(), Wait() error. The runner verifies the protocol, drains pipes and reaps the process group. Cancellation sends TERM, allows 15 seconds for cleanup, then KILL. UI stays open until Done. Before Start, final review requires the exact confirmation phrase; Start repeats validation. Sanitized stage and diagnostic events persist as private JSON Lines in a mode-0600 temporary log bounded to 8 MiB. Rotation keeps recent entries, including cleanup failures.

UI entry: ui.NewWithContext(ctx), followed by deferred Shutdown(). Main runs Bubble Tea with this context and handles SIGINT as a cancellation-request key; SIGTERM/SIGHUP cancel the context. A lifecycle mutex prevents queued commands from starting after shutdown, and running jobs are reaped before exit. English program strings/comments only. Minimum terminal 80x24; compact navigation below width 100. No percentage estimates. During install F2 toggles scrollable logs; Ctrl+C requests explicit abort, never immediate Quit; process completion controls exit eligibility.

Static networking captures the selected physical Ethernet adapter's validated unicast MAC address during preflight and rechecks it before erasure. The target udev rule assigns this adapter `voidnet0`; dhcpcd configuration uses that stable name. No MAC address supplied by the frontend is trusted. DHCP does not pin an adapter.

Security limitations: no protection against a hostile root process or hardware replacement that preserves identity. Fail closed on uncertain topology. Installation needs an already working wired live-session network; persistent Wi-Fi credentials are outside scope. Target is x86_64 glibc, 64-bit UEFI without Secure Boot. No rollback support; explicit subvol=@ boot configuration prevents Snapper default-subvolume rollback from selecting the boot root.

Software selection extends configuration v1 with `desktop` (`none`, `kde`, `niri`), `graphics` (`default`, `nvidia`), and `utilities` (the compatibility JSON key for additional packages). Missing/empty profile fields and null additional packages retain the original console-only behavior. `scripts/catalog.json` defines shared fixed desktop, common and input-method profiles; its legacy utilities list is no longer an installation allowlist. Both Go and Bash independently reject duplicate selections, package expressions/options, names longer than 128 ASCII characters and more than 256 additional packages. Go checks selected names against the chosen mirror's fetched package list again at Start. Bash independently queries each selected package's exact pkgname in that mirror's main repository, then resolves the full transaction and capacity before erasure. The `software` stage configures services, session launchers and input methods; package installation remains in `bootstrap`.

Packages replaces the fixed Utilities menu. The internal `--list-packages MIRROR` helper checks the Live environment, creates private temporary XBPS metadata, copies the Live signing keys, synchronizes only the selected `/current` repository and runs `xbps-query -i --repository=URL -s '*'`. Synchronization diagnostics go to stderr; only package records use stdout in this explicit listing mode. Target installation stdout remains JSON Lines. Existing configured repositories are ignored for listing and exact additional-package lookup. Go bounds output to 16 MiB, records to 64 KiB and package count to 100,000, parses names/versions/descriptions, sanitizes descriptions and sorts/deduplicates names. The TUI fetches asynchronously on entering Packages, searches names/descriptions locally, retains selections across filters, offers Ctrl+R retry/reload and clears the catalog and selections when the mirror changes. Main x86_64 glibc packages are supported; nonfree/multilib browsing is not enabled. NVIDIA retains its separate checked nonfree path. Package listing never installs packages or formats disks.

The optional `mirror` field is an HTTPS mirror root, including its deployment path (`/voidlinux`, `/void`, or another published path) but excluding `/current` and subrepositories. Go and Bash reject credentials, query/fragment strings, shell metacharacters, traversal and repository suffixes. Trailing slashes are normalized. An absent/empty value preserves the official default. TUI welcome preparation uses `--prepare-live`: the base guard validates root, official Void Live boot, x86_64/64-bit UEFI, Secure Boot, signing keys and mounted pseudo-filesystems without needing jq. It acquires the installer lock, checks the fixed Live-tool command set, and only when tools are missing runs separate XBPS self-update and Live-tool installation transactions using the Live repositories. It then repeats the full local requirements check. Failures stop discovery and retain the private preparation log, with R retry. `--check-local` and CLI `--check` remain non-mutating checks; the Mirror screen asynchronously runs `--check ROOT` before disk selection. Full selected-package preflight is repeated before erasure. `--mirror ROOT` works for the TUI and CLI `--check`. Repository configuration uses same-named `/etc/xbps.d` overrides of packaged files, preserving main/nonfree consistency after reboot.

The catalog's `fcitx` dependency bundle supplies all required Qt5/Qt6 and GTK3/GTK4 modules plus the config tool; only fcitx5 and Hangul remain user choices. Either choice adds the bundle. Graphical profiles configure PipeWire, WirePlumber, PulseAudio compatibility, ALSA routing and JACK library preference. KDE uses per-user XDG autostart; niri launches PipeWire directly. Packaged configuration fragments make PipeWire spawn WirePlumber and pipewire-pulse, preventing duplicate launch paths. KDE includes Konsole, display/login/audio settings and KWallet PAM integration; optional PAM modules preserve normal authentication failures/successes. Niri includes GNOME/GTK portals, GNOME Keyring and Seahorse; the portal override uses GTK file selection without Nautilus and GNOME Keyring secrets. Display variables are exported to D-Bus activation after niri starts. Keyring PAM login unlock and a session startup call are used without passing credentials in process arguments.

NVIDIA detection reads PCI sysfs display-class devices, including subsystem identities. The trusted installer executable is passed to Bash as `VOID_INSTALLER_HELPER`; `--check-nvidia VERSION` independently enumerates hardware and checks the exact repository driver's HTTPS current-products table with a bounded request. Legacy tables are excluded. The approved version is pinned before bootstrap; any unavailable document, unknown format or unmatched GPU blocks erasure. DKMS modules are checked after reconfiguration. No driver is loaded into the Live session.

KDE and niri use NetworkManager's internal DHCP client and a private keyfile, binding static IPv4 to the selected MAC. Competing interface-management services are disabled; desktop users join the network group. Console-only installations retain dhcpcd. Both desktops use the packaged SDDM runit service and elogind. Niri's session entry uses `dbus-run-session niri --session` because the upstream niri-session script supports systemd/dinit, not runit. Optional Fcitx5 is launched through KWin on Plasma or the niri config; GTK's native Wayland input is preserved without globally forcing GTK_IM_MODULE.

Common packages are selected from `catalog.json` by both Go and Bash: all profiles install bluez and tlp and enable bluetoothd and tlp. Final verification requires both service links. The TUI header and CLI receive the same build version.

Desktop selection and the optional NVIDIA driver are separate UI controls. Arrows move focus, Space selects a desktop, and Enter on a desktop selects it and continues. On the driver checkbox, Space toggles `[ ]`/`[V]` without changing the desktop. The checkbox retains the validated v1 `graphics` values internally. Root Btrfs formatting omits the filesystem label, and the root GPT partition name is explicitly empty. Mounts continue to use UUIDs.

Review renders independently of the normal header/sidebar/footer: a wide bordered dialog is centered horizontally and vertically on a black terminal-sized background. Only the summary scrolls; confirmation and Back/Install remain visible. The exact erase phrase enables Install, and Enter in the input only focuses that button. Enter on Install repeats configuration/password validation before scheduling the engine once. Returning to Review resets the phrase and focus. Tab/Shift+Tab and arrows navigate controls, Space selects/toggles, Enter confirms, and Esc returns. Account Tab wraps within the form; static-network mode and interface controls replace Ctrl+D/Ctrl+N with focus plus Space. Common Bluetooth/TLP selection is unchanged.

Live preparation runs through the same context-bound subprocess/log path as environment checks. Package-manager output goes to the private diagnostic log, while the Welcome screen displays preparation activity. The engine target-installation stdout event protocol is unchanged. No preparation runs on the development host; fixture tests replace the Live guard, lock and XBPS calls.

The normal header displays `Void Installer` on the left and the build version on the right of the same line, with two-column outer margins. Header padding is applied without a second width constraint to prevent the version from wrapping.

Welcome preparation emits fixed `VOID_PREP <stage> <status>` markers on stderr only in `--prepare-live` mode. Stages are environment/tools/xbps/install; statuses are running/completed/skipped. Go preserves all diagnostics in the private log and parses only these bounded, allowlisted markers. An asynchronous message channel carries preparation updates to the UI; discovery adds its own running/completed status and failures mark the active step failed. Cancellation remains tied to the model lifecycle and reaps the preparation job. The target installation JSON Lines protocol is unchanged.

Settings reserve a consistent bottom row for Continue. Account and static-network inputs advance to a separate Continue control; validation errors appear below the affected input and focus returns there. Lists retain Enter to confirm/continue and Tab to focus Continue. Desktop/utility descriptions reserve a fixed bottom area. Discovery exposes sanitized serial/WWN strings for display without changing the independent safety checks or identity comparison. Failed Welcome can open disk inspection with D, but inspection explicitly disables progression even if a disk itself is safe. Review places key choices before detailed packages/services/storage; smaller terminals use compact spacing while preserving erase confirmation. Installation previews recent sanitized diagnostics while retaining the full F2 log and cancellation handling.

Release automation lives in `.github/workflows/release.yml`. Main code pushes run `make check` and the race detector, then build and publish a release; documentation/image/LICENSE-only pushes and `[skip ci]` commits skip automatic CI. Manual dispatch on main requires no version input and runs those checks regardless of the skip marker. The workflow uses Asia/Seoul and GitHub-hosted ubuntu-latest runners, installing validation/release tools with apt. Test permissions are read-only; only the release job has contents-write permission. Workflow concurrency serializes runs without cancelling active releases.

`.github/scripts/prepare-release.sh` reads a numeric base version from `make version`, using the Makefile VERSION as the build/release source of truth. It selects the base tag or the first free positive revision suffix, considering both existing Git tags and all releases including drafts. It fails closed on GitHub API errors and identifies the newest published non-prerelease tag reachable from the tested commit. First releases include the full history; later notes list only new commit subjects with exactly seven hash characters under `## Changes`. Commit subjects are passed as data, never evaluated. With no new commits, the script outputs publish=false, removes stale notes and exits successfully; build/publication steps are then skipped. The build embeds the selected version without its leading v; packaging uses `void-tui-installer-vVERSION` and regenerates SHA256SUMS after naming the asset. GitHub CLI creates a draft against the exact tested SHA, uploads only the executable and checksum, then publishes it as a regular latest release. Existing tags/assets are never overwritten. No installer execution or disk access is part of CI. The default Make target remains build.
